# 「在线抓取」功能实现

**日期**：2026-08-23
**状态**：已批准，实施中

---

## 1. 背景

「01 选择内容」的第二个 Tab「在线抓取」上一轮只做了占位。本轮接入已部署的 feedgrab-x 服务（`https://importer-x.hitu.me`）：粘贴单条推文链接 → 抓取正文与互动数据 → 写入推文库并带入编辑框。

`docs/feedgrab-x/` 只作只读参考，不改其中任何代码。

## 2. 实测结论

| 项 | 结果 |
|---|---|
| `GET /health` | `ok:true`，`authRequired:true`，服务在线 |
| **CORS 预检** | `OPTIONS /import/twitter` → **405，无任何 `Access-Control-Allow-*` 头** |
| `POST /import/twitter` | 用真实 token 实测成功，返回 8.5KB JSON |

**浏览器无法直连该 API**，必须有服务端中转。这与接口文档第 11 行「网站后台只通过服务端调用它，前端页面不直接持有 token」的设计一致。

响应字段（实测 `https://x.com/xiaoxiaodong01/status/2063632975775125837`）：

- `thread.tweets[0].text` —— **主推文原文**（本轮取这个）
- `promptText` —— 主推 + thread 拼接（796 字）
- `date` `2026-06-07`、`authorHandle` `@xiaoxiaodong01`
- `metrics`：`likes 196 / views 15700 / retweets 34 / replies 33 / bookmarks 172`
- `source.url` / `source.tweetId`、`media[]`（4 张）

## 3. 已确认的决策

| 决策点 | 选定 |
|---|---|
| CORS | 本仓库新增 Cloudflare Pages Function 做同源转发 |
| Token | 访客自带，只存 `localStorage`，不进代码库、不进部署产物 |
| 正文取值 | 只取主推文原文 `thread.tweets[0].text` |
| 结果去向 | 写入推文库（`localStorage["tcs-posts"]`）+ 选中上卡 + 带入编辑框 |

「写入 json 数据文件」在纯静态站上落地为写 `localStorage["tcs-posts"]`——这正是现有推文库的持久化机制（`POSTS_KEY`），与「导入推文库 JSON」「X API 同步」走同一条路。

## 4. 实施细节

### 4.1 `functions/api/importer.js`

Pages 自动把它部署成 `/api/importer`，与站点同源，绕开 CORS。职责只有转发。

**SSRF 防护是必须项**：前端可在设置里改接口地址，如果 Function 无脑转发任意 URL，站点就成了开放代理——任何人都能让 Cloudflare 的服务器去请求任意地址。故强制校验：协议必须 `https`，host 必须在白名单（默认 `importer-x.hitu.me`，可由环境变量 `IMPORTER_ALLOW_HOSTS` 扩展）内，否则 400 拒绝。

token 从请求头取而非 body（body 更容易被日志留存）。优先访客自带，其次 `env.X_IMPORTER_TOKEN` 兜底（默认不配，即纯 BYOK）。

请求体固定 `includeRaw:false`，`timeoutSeconds` 默认 90（文档允许 10–180，留余量降低 Function 等待超时概率）。

### 4.2 「02 在线抓取」面板

齿轮按钮放 `.section-heading` 右侧（`margin-left:auto` 推过去，不动原有 flex 规则），点击切换设置区显隐。设置区默认收起，含接口地址、访问令牌、保存/清除。

新增 id：`importer-settings` / `importer-toggle` / `importer-url` / `importer-token` / `importer-save` / `importer-clear` / `fetch-status`；沿用 `fetch-url` / `fetch-go`（去掉 `disabled`）。

### 4.3 配置读写

新增 localStorage key `tcs-importer`，存 `{ url, token }`。与现有 `tcs-xkey` 同一套思路：只存本机、可一键清除、加载时回填。

### 4.4 抓取与入库

字段映射（`retweets` → `reposts` 是唯一需要改名的）：

```js
{
  id: "x-" + source.tweetId,
  date: d.date || todayISO(),
  text: d.thread?.tweets?.[0]?.text || d.promptText || "",
  sourceUrl: d.source?.url || "",
  topic: "在线抓取",
  metrics: { likes, replies, reposts: metrics.retweets, bookmarks, views },
}
```

**去重**：按 `sourceUrl` 或 id 查已有条目，命中则替换（更新互动数据）而非追加。新条目 `unshift` 到最前。

持久化沿用现有写法（`try/catch` + 库太大时 alert）。

错误码按接口文档翻译成人话：400 链接无效 / 401 令牌失效 / 502 抓取失败 / 504 超时 / **404 本地没跑 Function（提示改用 wrangler）**。

### 4.5 开发方式变更

加了 Function 之后，**验证抓取功能必须用 `npx wrangler pages dev .`**（python 起的服务下 `/api/importer` 是 404）。写进 CLAUDE.md。

## 5. 安全性说明

token 只存访客本地浏览器，不写进部署产物——`functions/` 里没有任何硬编码 token。

但有个前提要点明：**这个 token 是部署者私有的**，不像 X API Bearer Token 那样人人可自行申请。所以「访客自带 token」实际意味着只有持有者本人能用这个功能。若以后想对所有访客开放，把 token 配成 Cloudflare 环境变量即可（Function 已预留 `env.X_IMPORTER_TOKEN` 分支），但那样所有人都会消耗该抓取服务。

`docs/feedgrab-x/` 已在上一轮加进 `.gitignore`，其中的 `.env` 与 `sessions/` 不会进仓库。
