**日期**：2026-08-23
**状态**：已批准，实施中

## 1. 背景与目标

当前 `.workspace` 是两栏 `grid: 400px 1fr`（styles.css:50-53），左侧栏纵向堆了 7 个分组，很长；而预览区 732px 宽里 stage 只占 540px，**左右各 96px 是纯马赛克留白**——空间分配失衡。

本轮三件事：

1. 改成左中右三栏，右栏宽度样式与左栏一致
2. 把左栏的「03 样式」「04 背景」整体迁到右栏
3. 在迁过去的「样式」卡内新增「背景压暗」「正文字号」两个滑块

参考站：`https://dontbesilent-tweet-card-studio.vercel.app`

### 参考站实测参数

| 滑块 | min–max | 默认 | 实现方式 |
|---|---|---|---|
| 背景压暗 | 0–55 | 16 | 背景 `<img class="canvas-background">` 上盖 `<div class="canvas-dim">`，`background: rgba(0,0,0,.16)` |
| 正文字号 | 14–23 px | 18 | 直接设正文 `font-size` |
| 卡片透明度 | 55–100 | 100 | 本项目已有同名滑块（30–100） |

「卡片透明度」本项目已存在（`state.cardOpacity`），本轮不新建，只是随「样式」卡一起搬到右栏、与两个新滑块相邻。

## 4. 实施细节

### 4.1 三栏布局

用 `grid-template-areas` 表达三种形态，避免断点里重排 DOM 顺序：

```css
.workspace {
  max-width: 1480px;                                  /* 原 1200px */
  grid-template-columns: 400px minmax(0, 1fr) 400px;  /* 原 400px 1fr */
  grid-template-areas: "left preview right";
}
.control-panel       { grid-area: left; }
.preview-panel       { grid-area: preview; }
.control-panel-right { grid-area: right; }

@media (max-width: 1279px) {                          /* 新增：退两栏 */
  .workspace {
    grid-template-columns: 400px minmax(0, 1fr);
    grid-template-areas: "left preview" "right preview";
  }
}
@media (max-width: 980px) {                           /* 现有：单列 */
  .workspace { grid-template-columns: 1fr; grid-template-areas: "left" "preview" "right"; }
}
```

**单列顺序为什么是 左栏 → 预览 → 右栏**：符合「先选内容 → 看效果 → 调样式」的工作流；样式类控件放在预览下方，调的时候向上一眼就能看到结果。

`.preview-panel` 的 `position:sticky` 依赖 `.workspace{align-items:start}`，该声明保留不动。

**不需要动 `fitStageScale()`**：中列 592 − padding 余量 24 = 568 > 540，`Math.min(1, …)` 仍是 1，stage 保持 1:1。

### 4.2 迁移「03 样式」「04 背景」

index.html:73-113 是连续整块，剪切到新建的右栏容器（插在 `.preview-panel` 结束之后、`.workspace` 结束之前）：

```html
<aside class="control-panel control-panel-right">
  ...（原 73-113 两段原样粘贴）
</aside>
```

- 右栏复用 `.control-panel` 类拿到完全一致的样式，`.control-panel-right` 只用于 `grid-area` 定位
- 内部所有子样式（`.segmented` / `.option-grid` / `.bg-grid` / `input[type=range]`）都是全局类选择器，迁移后**零改动**
- app.js 全部走 `getElementById`，无 `closest`/`parentNode` 类结构依赖，**迁移不打破任何 JS**
- `#bg-section` 这个 id 在 js/css 中均无引用，原样带走

**分组编号重排**：左右各自独立编号。左栏 `01 选择内容 / 02 推文库·写文案 / 03 账号信息 / 04 X API / 05 交给 AI Agent`，右栏 `01 样式 / 02 背景`。

### 4.3 两个新滑块

复刻既有模板（`div.option.full` > `span.mini-label` + `em#xxx-val` + `input[type=range]`），插在「卡片透明度」之后：

| 滑块 | id | min–max | 默认 | URL 参数 | state |
|---|---|---|---|---|---|
| 背景压暗 | `bg-dim` / `dim-val` | 0–55 | **0** | `dim` | `bgDim` |
| 正文字号 | `body-size` / `bodysize-val` | 14–24 | **17** | `fontsize` | `bodySize` |

默认 17 = 当前 `.tc-body` 基准字号，保证默认态出图逐像素不变。

#### 正文字号：分档从绝对 px 改为相对倍率

styles.css:188-191 现为 17 / 15 / 13 / 11.5 px，换算成倍率 1 / 0.88 / 0.76 / 0.68：

```css
.tc-body         { font-size: var(--tc-body-size, 17px); line-height: 1.62; }
.tc-body.size-m  { font-size: calc(var(--tc-body-size, 17px) * 0.88); line-height: 1.58; }
.tc-body.size-s  { font-size: calc(var(--tc-body-size, 17px) * 0.76); line-height: 1.55; }
.tc-body.size-xs { font-size: calc(var(--tc-body-size, 17px) * 0.68); line-height: 1.5; }
```

`line-height` 是无单位倍率，自动跟随字号，四档现值原样保留。

变量写在 `#tc-body` 的 inline style 上。**关键**：app.js:277 用 `body.className = …` 整体赋值会清空 class 列表，但不影响 `style` 属性——所以走 CSS 变量安全，走「加 class」会被下次渲染抹掉。

导出侧无需改动：字号已在 `captureCardCanvas()` 光栅化时生效。

#### 背景压暗：预览用遮罩层，导出用 fillRect

```html
<div class="stage-dim" id="stage-dim"></div>   <!-- 插在 #stage-bg 之后 -->
```
```css
.stage-dim { position: absolute; inset: 0; background: #000; opacity: 0; pointer-events: none; }
.stage.card-only .stage-dim { display: none; }
```

**为什么用遮罩层而不是 `filter: brightness()`**：`opacity` 叠黑层与 canvas 的 `fillRect(rgba(0,0,0,a))` 是同一套 source-over 混合数学，预览与导出能逐像素对齐；`brightness()` 是乘法，两者不等价。

`pointer-events:none` 必须加，否则会吃掉卡片拖拽的指针事件。层叠顺序天然正确：`.stage-bg`(absolute) → `.stage-dim`(absolute) → `.safe-guides`(z-index:5) → `.tweet-card`(relative)。

`.stage.card-only .stage-dim{display:none}` 必须加，否则透明模式预览会出现凭空黑幕。

导出侧两条管线各插一段，位置是「背景已铺满、卡片阴影尚未开始」的那道缝：

- `composePoster()` — `drawCover(...)` 之后、`ctx.save()` 之前
- `exportLive()` — 逐帧 `drawCover(...)` 之后、`ctx.save()` 之前

```js
if (state.bgDim > 0) { ctx.fillStyle = `rgba(0,0,0,${state.bgDim / 100})`; ctx.fillRect(0, 0, W, H); }
```

必须放在 `ctx.save()` **之前**——之后会被阴影参数污染，fillRect 也会投影。

`card` 模式天然隔离：`captureCardCanvas()` 以 `#tweet-card` 为根节点，`#stage-dim` 是兄弟节点不在捕获树内。UI 上照既有范式在 card 模式隐藏「背景压暗」滑块。

### 4.4 URL 参数三处同步

- `applyUrlParams()`：`clampNum(q.get("dim"), 0, 55, …)`、`fontsize` 14–24
- `buildShareUrl()`：`bgDim !== 0`、`bodySize !== 17` 才写入

## 5. 附带修复

### 5.1 llms.txt 编码回 UTF-8

已核实 `e7269a5` 是 UTF-8、`83cc840` 变成了 GBK，是上一轮改动引入的回归。它是给 AI Agent 读的对外文档，GBK 会让绝大多数消费方读成乱码。用 Python 以 `gb18030` 读、`utf-8` 写回，CRLF 保留。

**本轮所有对 llms.txt 的编辑必须在转码之后进行。**

### 5.2 滑块 value 回写

现全项目没有任何代码把 state 写回 `<input type=range>.value`。打开 `?scale=120` 时卡片按 120% 渲染、标签显示 120%，但滑块拇指仍停在 95。本轮新增两个滑块会继承同一问题，顺手统一修：`applyUrlParams()` 之后调一次 `syncSliderInputs()`。
