## 三、根因分析

### 3.1 「页面宽度」问题的真相与用户描述相反

用户观察到的是「本地是全宽」，**实测恰好相反**：本地 `.workspace` 与在线版同为 1200px，塌缩的是 `.hero` —— 它被压到 765px 并居中，导致标题区左边缘比下方控制面板右偏 217px，视觉上呈现为严重错位。

### 3.2 塌缩链路

```
index.html:  <main class="app-shell">          ← 在线版没有这一层
styles.css:  .app-shell { display: flex; flex-direction: column; }
             .hero { max-width: 1200px; margin: 0 auto; }   ← 缺 width
```

`.hero` 作为 flex item，横向是**交叉轴**。CSS Flexbox 规范中 `margin: 0 auto` 会**抑制 `align-items: stretch`**，元素退化为 `fit-content` 宽度：

```
内容最宽项 = .hero p 的 max-width: 720px
+ .hero 左右 padding 1.5rem × 2 = 45px（15px 根字号）
= 765px  ← 与实测完全吻合
```

`.workspace` 因为显式写了 `width: 100%` 逃过一劫，所以只有 hero 塌缩 —— 这正是错位的来源。

### 3.3 为什么修根因而非打补丁

给 `.hero` 补 `width: 100%` 能治标，但 `.app-shell` 的 flex 容器仍在，任何未来新增的、只写 `max-width + margin:auto` 的直接子元素都会重蹈覆辙。

**采纳方案**：保留 `<main class="app-shell">`（`<main>` 是无障碍地标，有语义价值，不应为对齐而删），但**移除其 flex 布局**。`min-height: 100vh` 在 flex 移除后对本页无实际作用（内容高 2900px+ 远超视口），一并去掉，只留一个空 class 供 JS/未来使用则无意义 —— 直接删除该 CSS 规则，让 `<main>` 回归普通块级元素，行为与在线版 body 直接子元素完全一致。

## 四、改动清单

### 4.1 styles.css（12 处）

| # | 项 | 改动 | 理由 |
|---|---|---|---|
| 1 | `:root` | 删 `font-size: 15px` | 对齐在线版默认 16px |
| 2 | `.app-shell` | **删除整条规则** | 消除 hero 塌缩根因 |
| 3 | `.hero h1` | `letter-spacing: 0` → `-0.03em` | 在线版字距 |
| 4 | `.hero-agent` | 去 `!important` | 在线版无，且无冲突需要压制 |
| 5 | `.workspace` | 去 `width: 100%` | 根因已除，对齐在线版 |
| 6 | `.topnav-back` | 加 `transition: color .15s` | 在线版有 |
| 7 | `.topnav-back span` | → `.topnav-back svg { width:14px; height:14px }` | 配合 HTML 换 SVG 箭头 |
| 8 | `.drag-hint` | 删除第 177 行的重复定义 | 与 140 行完全重复 |
| 9 | `.footer` | 补 `.footer a { color: var(--accent) }` | 对齐在线版显式声明 |
| 10 | 安全区注释 | 补上具体像素值说明 | 对齐在线版注释 |
| 11 | `body.embed` 注释 | 补 Agent 用途说明 | 对齐在线版 |
| 12 | `.export-sheet` 注释 | 补 iOS 拦截原因 | 对齐在线版 |

**刻意保留、不对齐的一项**：

- `.preview-panel { min-width: 0 }` —— 在线版没有。这是 grid item 防溢出的防御性声明（grid `1fr` 默认 `min-width:auto`，超长不换行内容会撑破布局），**不产生任何视觉差异**。git 历史显示它出自「顶栏防挤压」那次移动端修复。移除它没有收益，只有风险，故保留。

### 4.2 index.html

**head（补 SEO，换本站身份）**

- title → `推文卡片生成器 | 推文一键做成抖音小红书图片卡片 — OPC Tweet Card Studio`
  （采用在线版关键词结构，站点名保留本 fork 的 OPC 标识）
