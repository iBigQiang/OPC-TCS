# 「选择内容」三 Tab 改造 + 首屏默认上卡

**日期**：2026-08-23
**状态**：已批准，实施中

---

## 1. 背景与目标

「01 选择内容」目前是两个按钮（自定义文案 / 推文库），默认停在「自定义文案」，导致**首屏卡片正文是空的**——新访客看到的是一张只有头像和互动数据的空壳卡（高度仅 133px），不知道这工具是干嘛的。该问题在上一轮迭代的 DEVLOG 中已记为待议项。

本轮：

1. 改成三个按钮，从左到右 **推文库 / 在线抓取 / 自由编辑**（原「自定义文案」改名）
2. 首屏默认落在「推文库」，并自动把**最新一条**上卡
3. 切到「自由编辑」时，把推文库里选中的那条带进编辑框，可以接着改而不用重敲或重新复制；「写文案」改名「编辑文案」
4. 「在线抓取」本轮只做占位

## 2. 已确认的决策

| 决策点 | 选定 |
|---|---|
| 「在线抓取」将来做什么 | 贴单条推文链接，抓正文 + 互动数据直接上卡 |
| 现阶段表现 | 点击后展开占位区块，写明即将上线 |
| 带入策略 | 智能带入：编辑框为空、或内容与上次带入的原文一致（没改过）才覆盖；改过的内容永不冲掉 |

## 3. 现状链路

摸清后发现改动量比预想小：

- `loadPosts()` 末尾 `.sort((a,b) => a.date < b.date ? 1 : -1)` —— posts **已按日期倒序**，`state.filtered[0]` 就是列表最上面那条
- `init()` 末尾**已经有** `else if (state.posts.length) selectPost(state.posts[0])` —— 只因 `state.tab` 默认是 `"custom"` 才从未走到。**把默认值改掉即可自动上卡，不需要新写选中逻辑**
- `.segmented` 是 `display:flex` + 子项 `flex:1`，三个按钮自动等分，**CSS 无需改动**
- `renderCard()` / `buildShareUrl()` / 「复制文案」/ 导出文件名 tag 都是 `state.tab === "custom" ? A : B` 的二分判断，新增的 `fetch` 值天然落到 B 分支（显示当前选中的推文），**无需改动**

## 4. 实施细节

### 4.1 三个 Tab

```html
<div class="segmented" role="tablist">
  <button id="tab-library" class="active">推文库</button>
  <button id="tab-fetch">在线抓取</button>
  <button id="tab-custom">自由编辑</button>
</div>
```

`active` 从 `tab-custom` 挪到 `tab-library`。副标题「直接写文案，或从推文库里选」→「从推文库选一条，或自己写」（顺序与按钮一致）。

### 4.2 三个互斥区块

三个都是编号 02（互斥显示共用一个位次，沿用现有做法）：

| 区块 | 默认 |
|---|---|
| `#library-section` | **去掉** `hidden` |
| `#fetch-section` | 新建，带 `hidden` |
| `#custom-section` | **加上** `hidden`，标题「写文案」→「编辑文案」 |

`#fetch-section` 占位内容：`disabled` 的 URL 输入框 + `disabled` 的「抓取」按钮 + 说明文字（写明即将上线、将支持什么，并指路现有左栏「04 用 X API 同步推文」做批量导入）。控件保持 disabled 而非隐藏，是为了让人一眼看懂将来长什么样。

### 4.3 「重新带入」出口

智能带入的代价：用户改过内容后，再选新推文切回来不会覆盖。必须给一个显式出口，否则会让人困惑「为什么没带进来」：

```html
<button class="chip" id="custom-reseed">用推文库选中的那条替换</button>
```

### 4.4 带入逻辑

```js
function primeCustomText(force) {
  if (!state.selected) return;
  if (!force && state.customText.trim() && state.customText !== state.customSeed) return;
  state.customText = state.selected.text;
  state.customSeed = state.selected.text;
  $("custom-text").value = state.customText;
}
```

`state.customSeed` 记录上次带入的原文。`#custom-text` 的 `oninput` 只更新 `customText` 不动 `customSeed`，所以用户一改两者就不等，即判定为「改过」。

### 4.5 init 首屏上卡

```js
else if (state.filtered.length || state.posts.length) selectPost(state.filtered[0] || state.posts[0]);
```

**URL 带 `text` 参数时不受影响**：`applyUrlParams()` 会把 tab 置成 `custom` 走原分支；此时 `state.selected` 仍是 null，`primeCustomText()` 首行就 return，不会覆盖链接传入的文案。

## 5. 行为变更提示

embed 模式若**不带 `text` 参数**，此前渲染「写点什么……」占位文字，改后会渲染推文库最新一条。带 `text` 的链接（Agent 的标准用法、「复制链接」生成的链接）完全不受影响。

## 6. 验证清单

1. 首屏：落在「推文库」、列表首条高亮、卡片正文 = 该条推文、卡片高度正常
2. 三 Tab 严格互斥，active 态跟随
3. 带入（未改过）：选 A → 切编辑（带入 A）→ 选 B → 切编辑（覆盖成 B）
4. 带入（改过）：带入 A 后改字 → 选 B → 切编辑（**保留改过的**）→ 点「替换」（变成 B）
5. `?text=测试` 打开，落在自由编辑且正文是「测试」，未被推文库覆盖
6. 在线抓取占位：区块展开，控件禁用态，说明可读
7. 三条导出管线 embed 回归
8. 三个 tab 下「复制文案」「复制链接」取值正确
